1. Preserve pool=all instead of always returning only main candidates
File: /Users/maybee/TradingAgents-AShare/api/services/tradeflow_service.py
Relevant area: get_candidates() return path

When callers request pool=all or a pool that should include data-gap/filtered candidates,
the current return path exposes only pool_result.main_candidates as candidates.
That drops observation and gate-filtered rows from the legacy candidate list, so existing
E2E/API consumers no longer see all three candidate types or correct summary counts.

2. Persist the gated pools, not the pre-gate top candidates
File: /Users/maybee/TradingAgents-AShare/tradingagents/tradeflow/discovery.py
Relevant area: save_candidates path after run_pool_gate()

After run_pool_gate() narrows plan_entries to main candidates and moves the rest into
observation/filtered pools, the save path still writes original top_candidates as active
DB candidates. Downstream DB readers such as Observe/detail/review cannot tell which
symbols were filtered or observation-only, causing API state to diverge from discovery
and allowing filtered candidates back into active workflows.
