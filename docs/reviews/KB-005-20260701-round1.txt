# TradingAgents-AShare — 项目协作规则

## 项目简介

A股智能投研多智能体系统，基于 LangGraph + LangChain 构建，模拟 14 名专业 Agent 的多空辩论与风控博弈，为投资者提供结构化的交易建议。

核心模块：
- **Agent 框架**：14 个多智能体（分析师/研究员/风控/交易员），LangGraph 编排
- **后端 API**：FastAPI，提供分析、持仓、定时任务、研报管理等接口
- **前端 UI**：React，意图驱动交互、辩论可视化、持仓看板
- **定时调度**：独立 scheduler，支持自选股定时分析
- **数据层**：AKShare + BaoStock + yfinance，SQLite 持久化

## 多工具协作架构

```
孟（最终决策）
  │
  ├── OpenClaw（主控调度）── 读取上下文 → 判断任务 → 派发执行
  │     ├── 简单任务：直接 exec 执行（git/python/npm）
  │     └── 复杂任务：sessions_spawn 子 agent 或调用 OpenCode 执行
  │
  ├── OpenCode（代码执行器）── 读取同一套上下文 → 改代码 → 跑测试 → 输出 diff
  │
  └── OpenCode TUI/Web（审查界面）── 查看 diff → 确认修改 → 做 review
```

**核心原则**：三者读取同一套项目上下文，不各自保存独立记忆。

## 开发与验收思维模式

### 功能开发：第一性原理 + 剃刀定律
- 开发新功能或修 bug 时，先回到问题本质：用户真正要解决什么、系统必须满足的最小事实是什么、哪些约束不能破坏。
- 默认选择能满足目标的最小实现，优先复用现有模块、数据契约和测试框架，不为“看起来完整”而堆叠复杂功能。
- 每个新增字段、接口、状态和抽象都必须能回答：为什么它不可少；如果删掉它，哪个明确场景会失败。
- 不用大改架构来解决局部问题；除非能证明现有结构已经无法承载目标。

### 功能验收/测试：多 Agent + 墨菲定律 + 对抗性审查
- 验收时默认假设：会遗漏的边界一定会遗漏，会被误用的字段一定会被误用，会超时/缺数据/脏状态的路径一定会发生。
- 重要改动必须至少从三类视角审查：实现者视角、用户操作视角、风控/数据真实性视角；必要时让不同 AI/Agent 分别做 diff review、测试回放和失败路径检查。
- 测试要覆盖失败、空数据、旧数据、字段缺失、重复执行、非交易日、脏工作区、接口顺序、状态迁移等最容易出事的路径。
- Codex review 或人工 review 必须优先找 P0/P1 风险，而不是复述功能亮点；发现问题先打回修复，再谈提交。

## 执行规则

### 代码修改前
1. 执行 `git status`，确认当前分支和未提交变更
2. 激活虚拟环境：`source .venv/bin/activate`
3. 确认修改范围不影响生产数据库（tradingagents.db）
4. 如果涉及核心模块，先跑一遍测试确认基线

### 代码修改后
1. 运行测试，全部通过才算完成
2. 输出：修改文件列表、测试结果、发现的风险点
3. 更新 `docs/DEVLOG.md`

### OpenClaw 调度方式
- **简单任务**（改配置、修 bug、小重构）：OpenClaw 直接 `exec` 执行
- **复杂任务**（新功能、跨模块修改）：调用 OpenCode 执行，由用户确认后执行
- **审查任务**：OpenClaw 不直接审查代码，提示用户用 OpenCode TUI 查看 diff

## 安全红线

- 不误改 `tradingagents.db`（生产数据库）
- 不误改 `eval_results/` 中的历史回测结果
- 不直接修改 `tradingagents/prompts/` 中的提示词模板（需走审批）
- 不删除 `logs/` 中的历史日志
- 测试数据不得写入生产数据库
- 不读取、解密、打印、提交任何模型 API Key 明文；只能使用 `HAS_KEY/NO_KEY` 级别的脱敏状态
- 除用户主动发起的分析/定时任务外，任何 live LLM API 调用前都要说明 provider、base_url、模型名和预计调用次数，并征得用户确认

# 项目说明

## 项目定位

TradingAgents-AShare 是一个面向 A 股投资者的多智能体投研系统，核心理念：

- **模拟真实投研机构**：14 个专业角色分工协作
- **多空辩论机制**：多头研究员 vs 空头研究员，研究总监裁决
- **多模型厂商支持**：OpenAI / Anthropic / Google / 智谱 / DeepSeek / 小米等
- **意图驱动交互**：自然语言输入，自动识别标的和周期
- **持仓追踪**：导入持仓，自动跟踪，连续分析

## 核心架构

### 1. 分析师团队（7 个）

| 角色 | 职责 | 数据源 |
|------|------|--------|
| 基本面分析师 | 财务指标、估值分析 | AKShare/BaoStock |
| 情绪分析师 | 社交媒体情绪、舆情 | AKShare |
| 新闻分析师 | 新闻事件、政策影响 | AKShare |
| 技术分析师 | K线形态、技术指标 | AKShare/BaoStock |
| 宏观分析师 | 宏观经济、利率环境 | AKShare |
| 主力资金分析师 | 大单流向、主力动向 | AKShare |
| 量价分析师 | 成交量、量价关系 | AKShare/BaoStock |

### 2. 研究员团队

- **多头研究员**：综合分析师结论，构建看多 Claim
- **空头研究员**：综合分析师结论，构建看空 Claim
- **研究总监**：裁决多空辩论，形成投资计划

### 3. 风控团队

- **风控经理**：评估风险、设置止损止盈
- **合规检查**：确保建议符合投资规范

### 4. 交易员

- 根据研究计划和风控要求，输出最终交易建议

### 5. 编排层

- **LangGraph**：状态图编排，控制 Agent 间信息流转
- **辩论机制**：多轮辩论，每轮有 Claim → Counter-Claim → 裁决

## 数据流

```
用户输入（自然语言）
  ↓
意图识别 → 标的 + 周期
  ↓
数据获取（7 路并行）
  ↓
分析师团队（7 个并行分析）
  ↓
研究员辩论（多轮）
  ↓
风控评估
  ↓
交易建议输出
  ↓
研报存储 + 通知推送
```

## 模型配置

系统支持多层模型配置：

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| `deep_think_llm` | 深度思考模型 | gpt-4o |
| `quick_think_llm` | 快速思考模型 | gpt-4o-mini |
| `mid_think_llm` | 中等思考模型 | gpt-4o |
| `ultra_think_llm` | 超深度思考模型 | gpt-4o |
| `backend_url` | API 端点 | https://api.openai.com/v1 |

支持通过环境变量或前端设置页切换模型厂商。

## API 接口

后端 FastAPI 提供以下主要接口：

- `POST /api/analyze` — 启动分析任务
- `GET /api/analysis/{id}` — 获取分析结果
- `GET /api/holdings` — 获取持仓
- `POST /api/watchlist` — 管理自选股
- `GET /api/reports` — 历史研报
- `POST /api/scheduler` — 定时任务管理

## 前端功能

- 意图驱动的自然语言交互
- 辩论对战可视化（多空对抗 Drawer）
- 持仓追踪与跟踪看板
- 结构化研报管理
- 定时分析配置
- 模型厂商设置

- `ready`：允许 `scripts/auto_dev_loop.sh` 自动领取。

# 架构决策记录

## ADR-001: 采用 LangGraph 编排多智能体
- **日期**：项目初始化
- **背景**：需要 14 个 Agent 按特定流程协作，有循环（辩论）和条件分支
- **决策**：使用 LangGraph 状态图编排，而非简单的链式调用
- **原因**：LangGraph 原生支持循环、条件路由、状态管理，适合辩论机制
- **影响**：所有 Agent 间通信通过 Graph State 传递，新增 Agent 需要注册到图中

## ADR-002: 多模型厂商适配层
- **日期**：项目初始化
- **背景**：不同 Agent 对模型能力需求不同，用户可能有不同的模型偏好
- **决策**：通过 `llm_clients/` 统一适配，支持通过配置切换厂商和模型
- **原因**：避免硬编码单一厂商，降低用户使用门槛
- **影响**：新增模型厂商需要在 `llm_clients/` 中添加适配器

## ADR-003: SQLite 作为持久化方案
- **日期**：项目初始化
- **背景**：需要存储研报、自选股、定时任务等结构化数据
- **决策**：使用 SQLite，单文件部署，无需额外数据库服务
- **原因**：本地部署场景，轻量级，零运维
- **影响**：并发写入有限，定时任务和分析任务需要串行化写入

## ADR-004: OpenClaw 作为项目协作调度层
- **日期**：2026-05-09
- **背景**：需要 OpenClaw、OpenCode、OpenCode TUI 三者协作处理同一项目
- **决策**：OpenClaw 负责任务判断和调度，不直接做代码修改；OpenCode 负责代码执行；OpenCode TUI 负责审查
- **原因**：OpenClaw 有完整的 agent 调度能力（exec / sessions_spawn / cron），适合做编排层
- **影响**：所有代码修改任务必须经过 OpenClaw 判断复杂度后决定执行路径

## ADR-005: Git 仓库 + docs/ 作为项目事实源
- **日期**：2026-05-09
- **背景**：多个工具需要读取同一套项目上下文

   230	def _split_frontmatter(text: str) -> Tuple[Optional[str], str]:
   231	    """把开头的 ``---\\n...\\n---`` frontmatter 与正文分离。
   232	
   233	    返回 ``(frontmatter_text_or_None, body_text)``。只匹配文件起始的 frontmatter，
   234	    避免误把正文中出现的 ``---``（如表格分隔符）当作边界。
   235	    """
   236	    if not text.startswith("---"):
   237	        return None, text
   238	    # 跳过第一个 ---，寻找下一个独占一行的 ---
   239	    lines = text.splitlines()
   240	    # lines[0] 应为 "---"
   241	    if not lines or lines[0].strip() != "---":
   242	        return None, text
   243	    end_idx = None
   244	    for idx in range(1, len(lines)):
   245	        if lines[idx].strip() == "---":
   246	            end_idx = idx
   247	            break
   248	    if end_idx is None:
   249	        return None, text
   250	    fm_text = "\n".join(lines[1:end_idx])
   251	    body = "\n".join(lines[end_idx + 1 :])
   252	    return fm_text, body

   285	            val = stripped[2:].strip()

   306	                    items = _split_list_items(inner)
   307	                    result[key] = items
   308	                else:
   309	                    result[key] = []

   311	            else:
   312	                result[key] = value.strip('"').strip("'")
   313	                current_key = key

   317	def _split_list_items(inner: str) -> List[str]:
   318	    """切分 ``[a, b, "c, d"]`` 形式的列表；保留引号内逗号。"""
   319	    items: List[str] = []
   320	    buf: List[str] = []
   321	    in_quote: Optional[str] = None
   322	    for ch in inner:
   323	        if ch in ('"', "'"):
   324	            if in_quote == ch:
   325	                in_quote = None
   326	            elif in_quote is None:
   327	                in_quote = ch
   328	            buf.append(ch)
   329	            continue
   330	        if ch == "," and in_quote is None:
   331	            items.append("".join(buf).strip())
   332	            buf = []
   333	            continue
   334	        buf.append(ch)
   335	    if buf:
   336	        items.append("".join(buf).strip())
   337	    return [it for it in items if it]

   406	def classify_page_type(
   407	    filename: str,
   408	    title: Optional[str],
   409	    frontmatter: Dict[str, Any],
   410	    section_headers: List[str],
   411	    body_hint_has_todo: bool,
   412	) -> str:
   413	    """识别 investment 页面类型。
   414	
   415	    返回 ``score_table`` / ``summary`` / ``to_be_supplemented`` /
   416	    ``company`` / ``industry`` / ``unclassified`` 之一。
   417	    """
   418	    name = filename
   419	    title_text = (title or "").lower()
   420	    name_text = name.lower()
   421	
   422	    # 待补充优先（KB-002 显式要求）。
   423	    if body_hint_has_todo or "待补充" in name or "待补充" in (title or ""):
   424	        return "to_be_supplemented"
   425	
   426	    # 评分表：标题/文件名命中关键词，或正文有 "标的列表" + 利好度/共识度。
   427	    if any(k in name or k in (title or "") for k in _SCORE_TABLE_KEYWORDS):
   428	        return "score_table"
   429	    joined_headers = " | ".join(section_headers)
   430	    if "标的列表" in joined_headers and ("利好度" in joined_headers or "共识度" in joined_headers):
   431	        return "score_table"
   432	
   433	    # 汇总表/速查表。
   434	    if any(k in name or k in (title or "") for k in _SUMMARY_TABLE_KEYWORDS):
   435	        return "summary"
   436	
   437	    report_type = _safe_str(frontmatter.get("report_type")) or ""
   438	    symbols = frontmatter.get("symbols")
   439	    has_company_symbol = _is_nonempty_field(symbols) or bool(_STOCK_CODE_FILE_RE.search(name))
   440	
   441	    # 公司页：报告类型为公司类 或 文件名带 6 位股票代码 + 单标的。
   442	    if report_type in _COMPANY_REPORT_TYPES or any(k in report_type for k in ("公司", "财报")):
   443	        return "company"
   444	    if has_company_symbol and report_type and report_type not in _INDUSTRY_REPORT_TYPES:
   445	        return "company"
   446	
   447	    # 行业页：报告类型为行业/周报/策略/深度/综述/产业链。
   448	    if report_type in _INDUSTRY_REPORT_TYPES or any(
   449	        k in report_type for k in ("行业", "周报", "策略", "深度", "综述", "产业链")
   450	    ):
   451	        return "industry"
   452	    if any(k in name or k in (title or "") for k in ("产业链", "行业", "周报", "策略", "综述")):
   453	        return "industry"
   454	
   455	    # 文件名带股票代码但无明确类型线索，倾向公司页。
   456	    if _STOCK_CODE_FILE_RE.search(name):
   457	        return "company"
   458	
   459	    # title/name 含 "评分"/"速查" 兜底。
   460	    if "评分" in name or "评分" in (title or ""):
   461	        return "score_table"
   462	
   463	    _ = (name_text, title_text)  # 保留以便后续扩展，避免未用告警
   464	    return "unclassified"

   467	def _compute_machine_readiness(page: WikiPageAudit) -> str:
   468	    """根据缺失字段与章节计算 machine_readiness: high/medium/low。"""
   469	    if page.is_to_be_supplemented:
   470	        return "low"
   471	    score = 0
   472	    total = 0
   473	    checks = [
   474	        page.has_summary_section,
   475	        page.has_risk_section,
   476	        page.has_sources_field,
   477	        page.has_symbols_field,
   478	        page.has_themes_field,
   479	    ]
   480	    for c in checks:
   481	        total += 1
   482	        if c:
   483	            score += 1
   484	    # 缺推荐字段越少，readiness 越高。
   485	    missing_penalty = len(page.missing_recommended_fields)
   486	    ratio = score / total if total else 0.0
   487	    if ratio >= 0.8 and missing_penalty <= 2:
   488	        return "high"
   489	    if ratio >= 0.4 and missing_penalty <= 5:
   490	        return "medium"
   491	    return "low"

   497	def _audit_single_page(rel_path: str, abs_path: Path) -> WikiPageAudit:
   498	    """审计单个 investment markdown 页面（只读）。"""

   501	    frontmatter = _parse_frontmatter(fm_text)

   504	
   505	    fm_fields: List[str] = list(frontmatter.keys()) if frontmatter else []
   506	
   507	    title = _safe_str(frontmatter.get("title")) or abs_path.stem

   517	    has_risk = _any_match(section_headers, RISK_SECTION_PATTERNS)
   518	    has_sources_section = _any_match(section_headers, SOURCES_SECTION_PATTERNS)
   519

   521	    has_symbols_field = _is_nonempty_field(frontmatter.get("symbols"))
   522	    has_themes_field = _is_nonempty_field(frontmatter.get("themes"))
   523	
   524	    missing_rec = [
   525	        f for f in RECOMMENDED_MACHINE_FIELDS if not _is_nonempty_field(frontmatter.get(f))

   529	    stale_high = stale_val in ("高", "high", "HIGH", "高（需更新）")

   535	        rel_path=rel_path,
   536	        title=title,

   539	        frontmatter_fields=fm_fields,
   540	        section_headers=section_headers,
   541	        has_summary_section=has_summary,
   542	        has_risk_section=has_risk,
   543	        has_sources_section=has_sources_section,

   545	        has_symbols_field=has_symbols_field,
   546	        has_themes_field=has_themes_field,

   548	        is_to_be_supplemented=body_has_todo or page_type == "to_be_supplemented",
   549	        stale_risk_high=stale_high,
   550	        valid_until_expired=_is_valid_until_expired(valid_until),
   551	        valid_until=valid_until,
   552	        updated_at=updated_at,
   553	        size_bytes=abs_path.stat().st_size if abs_path.exists() else 0,
   554	        line_count=text.count("\n") + (1 if text and not text.endswith("\n") else 0),
   555	    )
   556	    page.machine_readiness = _compute_machine_readiness(page)
   557	    return page
