Fixed the Codex round-1 finding (the CLI mutated `tradeflow.db` despite claiming read-only).

## Root cause
`scripts/run_mandate_daily_report.py:82-84` called `get_topic_heatmap()`, whose `_connect()` ran `candidate_engine.init_db()` (`CREATE/ALTER TABLE`) before reading — so even `--dry-run` mutated `tradeflow.db`.

## Changes
- **`api/services/tradeflow_service.py`** — `_connect(..., *, read_only=False)`: when `read_only=True`, skips `init_db()` and opens via SQLite URI `file:<abspath>?mode=ro` (genuinely immutable). `get_topic_heatmap(..., *, read_only=False)` propagates it and gracefully degrades to `no_data` when the table is missing in read-only mode.
- **`scripts/run_mandate_daily_report.py`** — `_load_topic_heatmap` now hard-codes `read_only=True`.
- **`tests/test_h016_mandate_daily_cli.py`** — added 2 regression tests: empty DB stays empty after load; stale-schema DB is not ALTER-migrated.
- **`docs/DEVLOG.md`** — added H-016 fix entry.

## Verification
- `tests/test_h016_mandate_daily_cli.py` → 13 passed (incl. 2 new).
- Full suite → **6945 passed, 17 skipped**.
- Manual: existing empty DB → `tables before: []` / `tables after: []` (previously `init_db` would create all tradeflow tables).

## Risk
In read-only mode a stale schema (missing newer columns) degrades to `trade_date`-only / `no_data` instead of auto-migrating — expected for read-only semantics. Production API still defaults to `read_only=False`, unchanged. Per constraints: **no commit**, no prompt/db changes.
