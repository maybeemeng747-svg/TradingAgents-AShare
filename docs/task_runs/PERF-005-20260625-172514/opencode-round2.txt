## Summary

**Root cause:** `_sample_single` accepts a `date_str` (today) for arg resolution but the freshness chain — `_is_stale_date` → `classify_source_status` → `classify_sample_result` — used the real wall clock (`datetime.now()`) instead. With today actually being 2026-06-25 and the test scenario's `as_of=2026-06-17` (a 1-day gap inside the test's `today="2026-06-18"`), data got misclassified as STALE.

**Fix:** Threaded an optional `today` parameter through all three functions (defaulting to `None` → current wall-clock behavior). `_sample_single` now passes `today=date_str` so stale checks evaluate against the correct reference date. Fully backward-compatible — existing callers in `fund_lhb_health.py` and DATA-018 tests are untouched.
